# COURTSIDE · 羽球局

纯前端单文件羽毛球双打工具。支持本机离线使用，以及 GitHub Pages + Supabase 云端共享。

先在“时间和地点 → 加地点”或“设置 → 地点和收费”填写球馆、每块场地的价格（按小时或每次预约）。安排球局时选地点、勾选 1～2 块场地，再填日期和开始／结束时间；结账自动带入场费。更改常用价格不会追溯修改当前预约或历史账单。

## 已实现

- 选场地、加球员后点“安排上场”排出阵容；也可在球场点“选人”指定四人和 A／B 两队。点名字可换人或互换位置。
- 保存阵容只会进入“待开打”，由你点“开始比赛”才正式开打。结算后自动选出的下一组也先等你确认，可以先调整阵容。
- 图标配短字，常用按钮适合手机点击；球员管理、使用说明和完整账单按需展开。单场为主球场加等待队列，双场桌面并排、手机切换查看。
- 比赛页直接显示球场、比分和候场名单，不重复显示步骤和人数卡片；完成场数在战绩页写明“今天完成 X 场”。更换场地从设置进入。
- 浅色简洁界面，独立的“场上 / 球员 / 战绩 / 结账”页面，避免所有信息挤在同一屏。
- 中英双语标题、按钮、字段、状态、提示和收款文案；球员姓名及用户填写的信息保留原文。
- 球员库、单人／批量新增、改名、今日签到、临时休息、今日已完成场次。
- 每人都有管理入口，可移出今日、删除或从“已删除”恢复。删除保留历史积分与战绩；已签到的人删除前会提示取消当前费用分摊。比赛中的球员须先结束或取消比赛再删除。
- 一块或两块场地独立排阵：自动从可上场球员中随机抽四人、随机分队；排除休息、未到场和另一场已占用的人。选人窗口可以再次随机抽取，也可以手动调整。
- 比分通过下拉菜单点选，不用打字；提供 15／21／30 分三种模式，默认 21 分。历史改分也可点选，场次不变。
- 比分结算、自动随机安排下一组、手动开打、撤下阵容、修改历史比分。重排正在进行的对阵不计该场战绩，需重新点开始；旧比分不会误算到新阵容。
- 每人今日上场次数、个人最近五场和比赛记录；没有排名、胜率排行或 Elo。
- 常用地点及场地收费、日期和预约时段；各场独立价格，支持半小时和跨午夜。预约保存收费快照，后续改价不改变旧账单。
- 按时或总额计算场地费；按桶或按只计算球费，支持桶价折算。
- 按签到名单平摊，显示两位小数，并明确说明几分钱的四舍五入尾差。
- 复制 WhatsApp 收款文案，球局归档，JSON 导入/导出备份。
- 云端观看链接、预授权组织者登录、服务器端排他操作锁、90 秒租约、版本冲突检查、重试幂等。

## 本机体验

直接用新版 Chrome 打开 `index.html`。无需安装运行依赖，也不依赖 CDN。

或者运行：

```sh
node server.mjs
```

打开 http://127.0.0.1:4173 。选择 1 块或 2 块场地，点“加人”填写姓名，再点“安排上场”。球场可“选人”调整两队，准备好后点“开始比赛”；多人姓名可按换行或逗号分隔。也可以在入口体验演示。
演示记录只保存在本机，页面会明确标记。第二个标签页默认只读，使用浏览器 Web Locks 保证同源只允许一个标签页修改。

## 配置 Supabase

1. 在 [Supabase Dashboard](https://supabase.com/dashboard) 新建项目。可使用已有项目；脚本只创建 `court_` 前缀的表和函数。
2. 进入 SQL Editor，运行本目录的 **完整 `supabase.sql`**。
3. 在 Authentication → Users 中创建组织者账号，使用你自己设置的邮箱和密码。按需要再创建备用组织者。不要把密码或 service_role key 发到聊天或写进代码。
4. 在 Authentication 的用户注册设置中关闭公众注册，仅使用预先创建的组织者账号。这样只有你的组织者可以创建新球局。
5. 在项目 API 设置中取得项目 URL 和 **publishable key**（旧项目可使用 anon key）。
6. 打开网页的“云端设置”，填写项目 URL、公钥并保存；登录组织者。
7. 选择“上传本机记录并创建”或“创建空白球局”。**正式使用时建议创建空白球局，避免上传演示战绩。**
8. 点击“分享”，把观看链接发给球友。链接包含一个随机观看凭证，持有链接的人可以看到该球局全部战绩、姓名、历史账单和收款信息，请仅分享给你的球友。
9. 需要另一个组织者接手时，由球局创建者在“云端设置”填写对方已创建的账号邮箱授权。当前操作人先“交出操作权”，对方登录并“接手操作”。

观看者不需要 GitHub 或 Supabase 账号。观看链接可读取数据，不授予修改权限。前端会拒绝 secret / service_role key。

### 同步与排他修改

- 观看端每 **5 秒** 读取云端快照。无需开启 Realtime publication，也无外部 JavaScript 依赖。
- 操作权绑定到登录用户和当前页面的随机设备凭证，**同一账号打开两页也只能有一页操作**。
- 心跳每 20 秒延长租约，租约 90 秒。正常离开页面会尽力释放，断网或崩溃后租约自动到期。
- 刷新操作页会生成新设备凭证：如果关闭时没有成功释放，需要等最多约 90 秒再接手。其他球友仍可查看。
- 暂停后台页面太久可能导致心跳超时；回到页面后重新接手即可。
- 同一浏览器多页通过 Web Locks 串行刷新登录凭证，并复用最新会话；一页退出后，其他页也停止使用该登录状态。迟到的刷新响应不会恢复已退出的会话。
- 成功打开观看链接后会记住该球局；同一浏览器的主屏幕应用从首页启动时会尝试恢复它。iOS 等系统可能给主屏幕应用独立存储，仍需在应用内首次打开观看链接。
- “创建空白球局”保留已选的一／两块场地，但不上传本机示例球员、战绩或账单。
- 写入必须在数据库中同时通过组织者身份、有效租约和版本号检查。网络中断后不接受离线修改，避免恢复联网时覆盖他人记录。
- 原始表与内部辅助函数不允许 anon / authenticated 直接访问；所有操作通过有限的 RPC 完成。
- 授权组织者只能在应用内交接；当前版本如需撤销组织者权限，由项目拥有者在 Supabase 删除对应 `court_editors` 行。若该人仍持有租约，同时清空该球局 holder 字段，或等待租约到期。

## 部署 GitHub Pages

基本网页只需要 `index.html`。要支持手机桌面图标和离线打开，还需上传 `manifest.webmanifest`、`sw.js`、`icon-192.png`、`icon-512.png`、`apple-touch-icon.png`。数据库脚本在 Supabase 执行，不需要额外服务器。

1. 在 GitHub 创建独立仓库，例如 `courtside`，将本项目文件上传。使用 GitHub Free 的 Pages 通常需要公开仓库，代码中不要写私密数据。
2. 仓库 Settings → Pages → Deploy from a branch，选择 `main` 和 `/ (root)`，保存。
3. 发布后打开 `https://你的用户名.github.io/courtside/`，按照上面的步骤连接 Supabase。
4. 从正式域名复制观看链接；**不要分享 `localhost` / `127.0.0.1` 链接**。

### 手机使用 / Mobile access

GitHub Pages 发布后，可以用手机流量或任意 Wi-Fi 打开，不依赖这台电脑在线。

- iPhone：用 Safari 打开网址，点“分享 → 添加到主屏幕”。
- Android：用 Chrome 打开网址，点菜单中的“添加到主屏幕 / 安装应用”。
- 首次打开后会缓存页面，之后可以离线打开本机记录；云端模式断网时仍为只读。
- 只有连接 Supabase 并创建云端球局后，不同设备才能查看同一份记录；网站上线本身不会自动同步 LocalStorage。

也可以预先在 `index.html` 的 `PUBLIC_CONFIG` 中填写项目 URL 和 publishable/anon 公钥，减少首次配置操作。这两项设计为可公开；不要填写数据库密码、登录密码、access/refresh token、secret key 或 service_role key。

## 轮转和计数规则

- 只有今日已签到、未休息、未在另一块场地比赛的人参与排阵。
- 等待名单按加入时间显示，但自动上场顺序和分队使用随机抽取，不再按等待先后安排。
- 刚结束比赛的四人回到队尾；迟到者和休息后返回者从加入时开始等待。
- 上场次数只计入已结算比赛，正在进行和已取消比赛不加次数。
- 比赛可选 15／21／30 分制，再点选 0～该上限的比分，双方不能同分。切换较低上限时，超出的已选分数会清空，需重新点选。旧备份较高的历史比分仍保留。
- 改分更新比赛结果，上场次数不变；不再计算排名或 Elo。旧备份中的积分字段可以保留，但不会用于显示或配队。
- “临时休息 / 离场”保留签到与费用分摊；取消签到则不再参与当前费用分摊。
- 排阵场地数量与费用中的计费场地数量独立，避免中途关掉一块场地后意外减少应付场租。
- 新球局归档旧球局签到、费用及收款信息，清空今日队列和计数，保留长期战绩。
- 目前是费用计算与收款文案助手，不执行转账，不包含逐人到账核销。

## 开发验证

应用本身零安装依赖。数据库测试使用开发依赖 PGlite，在本机 PostgreSQL 引擎中执行真实 SQL，并模拟 Supabase Auth 的身份与角色。

```sh
pnpm install --frozen-lockfile
pnpm test
```

测试覆盖：独立补场、公平等待、场次计数、手动选人和开打、休息与迟到、取消与重复结算、改分、地点收费和预约时间、费用尾差、价格快照和球局归档、数据库访问权限、同账号双页互斥、多人互斥、过期租约、交接、延迟心跳、版本冲突与写入重试。`tests/cloud-client.test.mjs` 运行实际客户端代码（关闭渲染、模拟网络），另覆盖观看链接恢复、多页凭证刷新、退出登录竞争、离线禁止修改和旧响应保护。

本机数据库测试不能替代真实 Supabase 项目的 Auth/PostgREST 网络联调。部署到实际项目后，应再用两个浏览器验证：观看链接只能读，组织者 A 持锁时 B 无法写入，A 交出后 B 能接手。
